## 问题描述

在Ubuntu中无法访问Windows磁盘，尝试挂载时出现错误提示。
![无法挂载windows磁盘](https://i.ibb.co/3YTnJ9Kj/2025-06-14-19-46-27.webp)

> 这到底是为什么呢？我有了一种猜测

### 猜测

有可能是windows没有完全关机，处于**神秘休眠**状态，导致Ubuntu无法访问Windows磁盘。

### 解决方案

### 1.关闭Windows快速启动

| 步骤 | 操作内容                                                                 |
| ---- | ------------------------------------------------------------------------ |
| 1    | 在Windows 11系统下，从控制面板进入到电源管理中。                         |
| 2    | 选择电源按钮的功能。                                                     |
| 3    | 发现没有快速启动设置项目，需要开启Windows 11的休眠功能。                 |
| 4    | 鼠标右键单击Windows徽标，选择管理员模式的Windows终端。                   |
| 5    | 在终端中输入`powercfg -h on`，回车开启休眠模式。                         |
| 6    | 再次进入Windows电源管理设置中。                                          |
| 7    | 点击选择电源按钮的功能，查看休眠和启用后快速启动是否出现在关机设置下面。 |
| 8    | 点击“更改当前不可用的设置”。                                             |
| 9    | 选择取消快速启动。                                                       |

> 这可能是只是**充分不必要**条件，但我还是建议关闭快速启动。

### 2.手动挂载分区

| 步骤                    | 操作方法                                                                                                                                                   | 相关说明                                                                                    |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 确认 Windows 状态       | 确保 Windows 系统完全关机，而非处于休眠状态。可重新登录 Windows 并重启后切换到 Ubuntu 系统。                                                               | 若 Windows 处于休眠状态，分区会被锁定，导致 Ubuntu 无法访问其文件。                         |
| 查看分区名              | 在 Ubuntu 系统中，打开终端，使用命令`sudo fdisk -l`查看磁盘分区情况，确定 Windows 文件所在的分区名。或者也可以在 Ubuntu 文件系统的“其他位置”中查看分区名。 | 该命令会列出所有磁盘分区信息，找到对应 Windows 系统的分区，通常分区名类似`/dev/nvme0n1p3`。 |
| 修复分区?(大概率不需要) | 使用命令`sudo ntfsfix /dev/nvme0n1p3`（其中`/dev/nvme0n1p3`是 可能的Windows 文件所在分区名，具体分区情况请自行查看）修复分区。                             | 若分区有错误或被锁定，该命令可以尝试修复分区，使其能够被正常访问。                          |
| 创建挂载点（如果需要）  | 如果提示挂载点不存在，使用命令`mkdir /media/megumi/Windows`（其中`megumi`是用户名，需根据实际情况修改）创建挂载点。                                        | 挂载点是用于挂载分区的目录，若不存在则需先创建。                                            |
| 挂载分区                | 使用命令`mount /dev/nvme0n1p3 /media/megumi/Windows`（其中`/dev/nvme0n1p3`是分区名，`/media/megumi/Windows`是挂载点，需根据实际情况修改）挂载分区。        | 挂载后即可通过挂载点访问 Windows 系统下的文件。                                             |

> 其他分区磁盘同理

:::tip

如果你手动化挂载之后

重启电脑却发现又不行了

可以试试**持久化方法**

:::

### 3.持久化挂载分区

| 步骤                   | 操作方法                                                                                                                                                                                               | 相关说明                                            |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------- |
| 找到分区的 UUID        | 在终端中输入命令 `sudo blkid` 查找 Windows 分区的 UUID。找到类似 `/dev/nvme0n1p3: UUID="12345678-1234-1234-1234-123456789012" TYPE="ntfs"` 的输出，记录下 UUID。                                       | UUID 是分区的唯一标识符，比设备名称更可靠。         |
| 创建挂载点             | 输入命令 `sudo mkdir -p /media/megumi/Windows` 创建挂载点（若尚未存在）。可将 `megumi` 替换为你的用户名。                                                                                              | 挂载点是用于挂载分区的目录。                        |
| 编辑 `/etc/fstab` 文件 | 使用文本编辑器（如 `sudo nano /etc/fstab`）打开 `/etc/fstab` 文件，在文件末尾添加一行：<br>`UUID=12345678-1234-1234-1234-123456789012 /media/megumi/Windows ntfs defaults 0 0`，将 UUID 替换为实际值。 | `/etc/fstab` 文件用于定义系统启动时自动挂载的分区。 |
| 保存并退出             | 若使用 `nano` 编辑器，按 `Ctrl+O` 保存，然后按 `Ctrl+X` 退出。                                                                                                                                         | 保存更改以确保配置生效。                            |
| 挂载并测试             | 输入命令 `sudo mount -a` 立即挂载所有在 `/etc/fstab` 中定义的分区。如无错误信息，检查挂载点是否可访问 Windows 分区文件。                                                                               | 测试配置是否正确，确保分区能够正常挂载。            |
| 设置挂载点权限（可选） | 输入命令 `sudo chmod -R a+rwx /media/megumi/Windows` 设置挂载点权限，以便普通用户也能访问挂载的分区。                                                                                                  | 如果不需要普通用户访问权限，可以跳过这一步。        |

> 其他分区磁盘同理
